"所有任务的""测试逻辑""是放在AIG-Eval这个框架里面吗？"	"不是的，任务的""测试逻辑""是任务自己带的（通过 config.yaml 指定的命令），框架只负责调度 Agent 并计算最终评分。"
AIG-Eval里面，读取任务的 config.yaml，把这些信息告诉 Agent（作为 prompt 的一部分）,为什么要这么设计呢，为什么要agent来自动去决策调用哪个命令？	"这个框架的目的不是简单地""跑一个优化脚本""，而是评测 AI Agent 的自主编程能力：也就是：给 Agent 目标，让它自己决定怎么做，Agent 可以尝试、失败、重试、调整策略，测试""Agent 能不能完成任务""。    假设编译失败了： 传统脚本：直接报错退出   make  # 失败 exit 1  # 结束 Agent：可以自主处理   make → 失败 → 分析错误信息 → 修复代码 → 重新编译 → 成功 这才是评测 Agent 智能程度的意义！ 框架只告诉 Agent""你要做什么""，不告诉它""你要怎么做""。"

AIG-Eval里面存在不确定性 是 Agent 评测的固有特点，这是为什么？	不确定性来源影响LLM 生成随机性（temperature）同样的 prompt 可能产生不同的优化策略Agent 探索路径不同可能先尝试 A 策略失败，再尝试 B；或直接成功多次迭代的不同Agent 可能迭代 3 次或 10 次才收敛
