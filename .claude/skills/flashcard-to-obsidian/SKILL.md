你正在执行 Flashcard 到 Obsidian 文章的完整 Pipeline。

【参数说明】
$0 = 输入文件（原始 flashcard 文件，例如：anki原始导出笔记/0209命运的笔记.txt）
$1 = 文章存放目录（例如：0209的笔记，文章将保存在：润色后的文章/0209的笔记/）

【输出文件自动推导】
润色后的 flashcard 文件（output_flashcard）从输入文件自动推导：
- 输入：`xxx/yyy.txt`（父目录 + 文件名）
- 输出：`xxx/yyy_output.txt`（相同父目录，文件名加 `_output` 后缀）
- 例如：`anki原始导出笔记/0209命运的笔记.txt` → `anki原始导出笔记/0209命运的笔记_output.txt`


====================
使用示例
====================

完整命令示例：

```
/flashcard-to-obsidian \
  anki原始导出笔记/0209命运的笔记.txt \
  0209的笔记
```

**执行结果**：
1. 自动生成润色后的 flashcard：`anki原始导出笔记/0209命运的笔记_output.txt`（从输入文件自动推导）
2. 生成 Obsidian 文章：`润色后的文章/0209的笔记/主题名.md`（多篇文章）
3. 不生成中间的主题分类文件（在内存中处理）


====================
Pipeline 概述
====================

这是一个三阶段处理流程，将原始 flashcard 文件转换为结构化的 Obsidian 文章：

1. **Stage 1：Flashcard 清洗与润色**
   - 润色问答对，统一格式为 `<问题> | <答案>`
   - 输出到自动推导的 output_flashcard（从 $0 推导：`xxx/yyy.txt` → `xxx/yyy_output.txt`）

2. **Stage 2：主题识别与分类**
   - 基于润色后的 flashcard，在内存中识别知识主题
   - 进行聚类分类，计算主题数量（总行数 ÷ 12，四舍五入）
   - **不生成中间文件**，主题信息仅在内存中处理

3. **Stage 3：生成 Obsidian 文章**
   - 根据识别的主题，从润色后的 flashcard 中提取对应问答对
   - 将问答对改写成自然段落
   - 生成 Obsidian 格式的文章，保存到指定目录


====================
Stage 1：Flashcard 清洗与润色
====================

【任务目标】
读取输入文件中的问答对（flashcard），针对表达进行优化，让表达更加流畅自然并且逻辑更清晰，对不准确的地方进行纠正，并统一格式输出。

【处理规则】
逐行处理，每一行是一个问答对：

1. 保持问答结构不变
2. 润色语言，使表达更加流畅自然、逻辑更清晰
3. 确保信息准确，如发现错误需纠正
4. 问题与答案必须包含完整上下文信息
5. 用户仅凭"问题"即可推理出答案
6. 问题部分不得丢失任何关键信息
7. 可以语言简化，但不能损失背景或要点
8. 最终统一格式为：

<问题> | <答案>

注意：
- 每行一个 flashcard
- 不要额外解释文字
- 不要空行
- 只输出最终结果内容

【重要关注点】
**保留所有关键信息，同时做到流畅**

这是处理过程中的核心原则：
- 信息完整性优先：不能为了流畅而丢失关键信息
- 表达优化其次：在保证信息完整的前提下，优化语言表达
- 平衡两者：既要保留所有关键信息，又要让表达流畅自然

【执行步骤】
1. 检查 $0 是否存在，不存在则报错停止
2. 从 $0 推导 output_flashcard：
   - 提取 $0 的父目录路径和文件名（不含扩展名）
   - 生成 output_flashcard = `{父目录}/{文件名}_output.txt`
   - 例如：`anki原始导出笔记/0209命运的笔记.txt` → `anki原始导出笔记/0209命运的笔记_output.txt`
3. 检查 output_flashcard 的目录是否存在且可写，如不存在则创建目录
4. 读取 $0 的全部内容
5. 逐行进行润色与标准化处理
6. 将结果写入 output_flashcard（UTF-8 编码，覆盖写入）


====================
Stage 2：主题识别与分类（内存处理）
====================

【任务目标】
基于 Stage1 输出的润色后 flashcard，在内存中识别主要知识主题，并进行聚类分类。

【分类原则】
1. 主题数量根据 flashcard 行数自动计算：总行数 ÷ 12，四舍五入
2. 主题之间必须边界清晰
3. 相似内容合并到同一主题
4. 每个主题给出：
   - 建议的文章标题（适合作为文章标题，而不仅仅是分类标签）
   - 覆盖的问答行号范围
5. 主题数量不宜过多，避免碎片化

【处理方式】
- **在内存中完成主题识别和分类**
- **不生成中间文件**
- 主题信息（标题、行号范围）保存在内存中，供 Stage 3 使用

【执行步骤】
1. 读取 output_flashcard（Stage1 输出的润色后 flashcard）的全部内容
2. 计算主题数量：
   - 统计文件总行数（每行代表一张闪卡）
   - 主题数量 = 总行数 ÷ 12，四舍五入
   - 例如：40 行 → 40÷12 = 3.33 → 四舍五入 = 3 个主题
3. 分析所有问答，根据计算出的主题数量进行识别和聚类
4. 在内存中保存主题信息：
   - 每个主题的建议文章标题
   - 每个主题对应的问答行号范围


====================
Stage 3：生成 Obsidian 文章
====================

【角色定位】
你是一位专业写作专家，擅长将问答形式的知识整理成流畅、内容丰富、详实、观点深刻的文章。

【任务目标】
根据 Stage2 识别的主题信息，从润色后的 flashcard 中提取对应问答对，每个主题分别整理成 1 篇 Obsidian 笔记。

【执行步骤】
1. 从内存中获取 Stage2 识别的所有主题信息（标题、行号范围）
2. 读取 output_flashcard（润色后的 flashcard）的全部内容
3. 对每个主题：
   - 根据行号范围，从 output_flashcard 中提取该主题对应的所有问答对内容
   - 将问答对改写成自然段落
   - 整合相似/重复的知识点
   - 添加双链、代码块、callout 等元素
   - 确保文章内容丰富、详实、观点深刻
4. 检查并创建输出目录：`润色后的文章/$1/`（如不存在则创建）
5. 将生成的文章写入：`润色后的文章/$1/主题名.md`
   - 使用主题的建议文章标题作为文件名

【写作规则】
1. **不要保留问答格式，改写成自然段落**
   - 将问答对转换为流畅的叙述性文章
   - 使用自然段落组织内容

2. **整合相似/重复的知识点**
   - 合并重复或相似的内容
   - 避免信息冗余

3. **使用双链连接相关概念**
   - 格式：[[其他文章名]]
   - 用于连接相关的概念和文章

4. **代码命令使用 bash 代码块**
   - 格式：```bash
   - 代码内容
   - ```

5. **重要提示使用 callout**
   - 支持的 callout 类型：`[!tip]`, `[!note]`, `[!danger]`, `[!warning]`, `[!info]`, `[!success]`, `[!question]`
   - **格式要求**：
     ```
     > [!info]
     > **title**：
     > - sentence1
     > - sentence2
     ```
   - **注意**：callout 格式中，感叹号标记符号前面需要有大于号 `>`，显示的内容以及所有 callout 标记符号前面都需要 `>`

6. **文章长度：800–1500 字为宜**
   - 确保内容丰富、详实、观点深刻

步骤 5：输出总结
最后仅输出：

✅ Pipeline 完成
输入文件: $0
输出文件: output_flashcard（自动推导）
