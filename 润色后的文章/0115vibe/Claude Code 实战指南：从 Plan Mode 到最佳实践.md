# Claude Code 实战指南：从 Plan Mode 到最佳实践

## 什么是 Plan Mode

Claude Code 的 Plan Mode 是一种特殊的协作模式，它不直接修改代码，而是先分析并制定计划。通过只读方式（读取文件和分析代码库）来理解需求，生成详细的执行计划，等待用户确认后再执行改动。

这种模式的核心价值在于**风险前置**——提前发现问题，避免在修改代码后才发现方向错误。期望目标是：将 plan 交给 Claude Code 修改后，能够一次性通过，没有逻辑和语义错误，可以完美运行并通过测试。

## 何时使用 Plan Mode

> [!warning] 使用 Plan Mode 的前提
> **重要**：不要一有 idea 就直接进入 Plan Mode！
>
> - 应该先在普通模式或其他工具（如 Cursor）中讨论和明确需求
> - 确保需求清晰后，再进入 Plan Mode
> - 进入 Plan Mode 意味着已进入修改阶段

### 判断标准

当你需要和 AI 聊清楚需求、理解背景时，**不应该使用 Plan Mode**，而应该使用普通模式。Plan Mode 适用于需求已经明确、需要制定详细执行计划的阶段。

### 使用 Plan Mode 时的注意事项

在 Claude Code 中使用 Plan Mode 时，需要：
- 输入明确的任务需求或已制定好的 plan
- 开启 **ultrathink** 功能以使用最大算力来思考计划

## plan.md 文件的价值

在让 Claude Code 执行任务之前，需要准备一个明确且无歧义的 plan.md 文件。这个文件不仅仅是一次性的计划文档，更应该放入代码仓库，与版本控制一起管理，作为整个开发过程的"真实记录"。

> [!tip] 结构化计划的优势
> **推荐做法**：
>
> - 将 plan.md、architecture.md 等文档纳入版本控制
> - 不依赖上下文窗口
> - 下次对话可以直接引用 plan.md
> - 方便与他人协作
> - 不会丢失历史讨论内容

## Claude Code 的正确定位

一个常见的心得总结是：**不要把 Claude Code 当作"立刻写代码的工具"**。

> [!success] Claude Code 的最佳定位
> **核心理念**：应该把它当作"联合设计者 + 执行者"来使用。
>
> - Plan Mode 完成后，先生成 Markdown 文档，而非立即执行
> - 先设计，再执行
> - 让 AI 参与整个思考过程，而不仅仅是代码生成

## 图片上传功能的使用

在使用 Claude Code 时，经常需要展示截图或设计稿进行讨论。

### 当前支持情况

现在 Claude Code 已支持图片上传功能。如果 Ctrl+V 或 Alt+V（Windows）无法直接上传，可以：

1. **截图到剪贴板后按 Ctrl+V / Alt+V**：成功上传后会显示类似 `[Image #]` 这样的附件提示
2. **将图片放到项目目录中**：通过 `@` 符号将图片导入

### 备用方案

如果无法上传图片，可以将截图发给 ChatGPT 或 Claude Web 进行看图分析，然后总结问题，将文字结论粘贴给 Claude Code。

## 自定义 Slash Command

Claude Code 允许在两个位置自定义 slash command，作用范围不同：

| 位置 | 作用范围 |
|------|----------|
| 当前项目下的 `.claude/commands` 目录 | 仅在该项目中可用 |
| 个人 home 目录下的 `~/.claude/commands` | 当前用户在任何项目中都可用 |

> [!info] 配置建议
> **使用场景**：
>
> - 项目特定的工作流脚本 → 放在项目 `.claude/commands`
> - 个人通用的工具命令 → 放在 `~/.claude/commands`

## 总结

Claude Code 是一个强大的 AI 辅助开发工具，但要发挥其最大价值，关键在于**正确理解和使用 Plan Mode**。记住：先在普通模式下理清需求，再进入 Plan Mode 制定计划，最后才执行代码修改。将这个过程产生的文档纳入版本控制，让 AI 成为真正的"联合设计者"。
