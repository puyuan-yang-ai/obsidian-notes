# 上下文管理：如何让 AI 更懂你的项目

AI 编程工具的能力上限，很大程度上取决于它对项目的理解深度。而理解深度，又取决于上下文（Context）的质量和数量。如何有效地管理上下文，让 AI"看得更远、更广"，是掌握这些工具的关键。

## 图片上传：CLI vs GUI 的产品形态差异

一个常见的误解是：Cursor 能轻松传图，而 Claude Code 让人感觉"不行"。**这不是模型差异，而是产品形态差异**。

- **Cursor** 是 GUI/IDE，天然有"附件上传"的 UI
- **Claude Code** 是 CLI，必须依赖终端对"拖拽/粘贴图片"的支持

> [!tip]
> **Claude Code 上传图片的两种方式**
> - 从剪贴板粘贴图片（最常用）：用 `Ctrl+V`（或 Windows 上的 `Alt+V`）粘贴
> - 把图片放到项目目录里，然后通过 `@` 方式引用图片路径

了解这个差异后，就不会再对 Claude Code 的图片上传能力感到困惑了——它不是做不到，只是实现方式不同。

## 扩展思考预算：让 AI 更深入地思考

Claude Code 支持通过关键字触发更高层级的思考模式：

- `think` — 基础扩展思考
- `think hard` — 中等扩展思考
- `think harder` — 高级扩展思考
- `ultrathink` — 分配最多思考预算

> [!info]
> **何时使用扩展思考模式**
> - 复杂的方案设计
> - 架构规划
> - 多种方案权衡
> - 需要深入推理和解释的任务

### 最佳实践：在计划阶段提升思考预算

> [!success]
> **官方推荐做法**
> "在计划/分析阶段提升思考预算，而不是在代码执行阶段反复深思。"

**规划阶段**（尤其是复杂任务、架构设计、方案选择）时开启更高思考模式（如 `ultrathink`），这是推荐做法，因为在 Plan Mode 里它会更彻底地分析整体结构/权衡策略。

**执行阶段**（真正要改代码时）一般不必须开启 `ultrathink`，执行阶段更侧重具体实现，而不是广泛方案比较。

### 触发方式：关键词 vs Tab 键

官方建议和社区大佬普遍认为：**用提示词 `think`、`think hard`、`think harder`、`ultrathink` 明确触发，比依赖 Tab 更稳定**。

```bash
# 推荐：直接在 prompt 中使用关键词
帮我 ultrathink 一下这个架构方案的优劣

# 不推荐：依赖 Tab 切换 thinking
# Tab 切换 thinking 在一些终端/设置下可能不被正确捕获
```

## Cursor 的 Max Mode：看得更远、更广

Cursor 提供了 **Max Mode**，通过最大上下文窗口（例如 1M tokens）来提升理解和分析能力。

| 模式 | 上下文范围 | 适用情境 | 优缺点 |
|------|------------|----------|--------|
| 普通模式 | 默认（如 200k） | 日常任务、一般代码补全 | 快速、成本低 |
| Max Mode | 最大（如 1M tokens） | 大型项目 & 复杂分析 | 信息更多、理解更好，但慢且更贵 |

> [!note]
> **Max Mode 的本质**
> 就是让 AI"睁大眼睛"，看得更远、更广，通过更大上下文来提升理解和分析能力，但这需要更多资源和成本。

## Cursor 的上下文机制：动态拼装

与 Claude Code 不同，Cursor **不会自动加载某个固定规则文件作为 system prompt**，而是采用**动态上下文拼装系统**。

### 上下文来源（按优先级）

1. **当前编辑文件**（最高权重）：正在打开/编辑的文件内容
2. **手动选中的文件/文件夹**（`@file`）
3. **最近打开的文件**（heuristic）
4. **Workspace rules**（`.cursor/rules/*.md`）

> [!tip]
> **Cursor vs Claude Code 的上下文机制**
> - Claude Code：规则文件自动加载型 Agent 系统，每 session 自动加载 CLAUDE.md
> - Cursor：动态上下文拼装型 IDE Copilot，按当前文件 + 手动上下文 + 会话历史拼装

## 访问控制：限制 AI 的"可见范围"

在使用 Claude Code 时，你可以限制它只能访问确定目录，其他目录不可访问。

```bash
# 启动时限制目录范围
cd /your/project/xxx/yyy && claude
```

这种方式启动后，Claude Code 默认只"看得到/操作得到" `yyy` 这个目录及其子目录：

- ✅ 可以读/写：`yyy/**`
- ❌ 看不到：`/your/project/xxx` 的其他兄弟目录
- ❌ 看不到：更上层目录（除非你授权）

> [!info]
> **Claude Code 的访问控制机制**
> 1. **限制访问/修改文件的权限**：在 `settings.json` 中使用 `allow/deny` 规则
> 2. **CLI 级别添加可访问目录**：使用 `--add-dir` 或 `/add-dir` 命令

## 总结

上下文管理的核心在于：**在合适的时候，给 AI 提供合适数量和质量的信息**。

- 在**规划阶段**，使用 `ultrathink` 让 AI 深入思考
- 在**大型项目分析**时，使用 Max Mode 让 AI 看得更广
- 在**需要安全隔离**时，限制 AI 的访问范围
- 在**日常使用**中，动态拼装上下文，而不是一股脑全部塞给 AI

掌握这些技巧，你就能让 AI 真正理解你的项目，而不是在浅层表面打转。
