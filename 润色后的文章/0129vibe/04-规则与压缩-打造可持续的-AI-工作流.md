# 规则与压缩：打造可持续的 AI 工作流

当你的项目越来越复杂，与 AI 的对话越来越长时，两个问题会变得日益突出：如何让 AI 持续遵守项目的规范？如何避免上下文长度爆炸？答案在于**规则文件系统**和**自动压缩机制**。

## 规则文件：CLAUDE.md vs .cursor/rules

### Claude Code：自动加载的 CLAUDE.md

Claude Code 的规则文件机制非常直接：每次新开一个 session，它会自动扫描项目根目录，找到 `CLAUDE.md`，然后作为 **system-level context/rules** 注入到模型（类似 system prompt）。

```bash
# CLAUDE.md 的加载机制
# ① 启动 session 时
# ② 扫描项目根目录
# ③ 找到 CLAUDE.md
# ④ 作为 system prompt 注入到模型
```

> [!tip]
> **CLAUDE.md 的作用**
> 定义项目规则/指导信息，给 AI 提供一致的上下文和规范，让生成结果更贴合项目需求。

### Cursor：动态加载的 .cursor/rules

Cursor 的机制完全不同。它不会自动加载某个固定规则文件，而是使用 **.cursor/rules/*.md** 目录下的规则文件。

> [!info]
> **Cursor 规则文件的最佳实践**
> - 推荐 `.mdc` 格式（带 frontmatter 的规则）
> - UI 里会出现下拉框，可以选择 `Always apply = true`
> - 文件里实际的文本是 `alwaysApply: true`
> - 行为是每次对话自动注入

```markdown
---
alwaysApply: true
---

# 项目规则

这里是规则内容...
```

当你把 `.md` 文件改成 `.mdc` 后，Cursor 才会把它当成"结构化规则文件"，UI 里才会出现 `Always apply` 下拉框。

### 两者对比

| 特性 | Claude Code | Cursor |
|------|-------------|--------|
| 规则文件位置 | `CLAUDE.md` | `.cursor/rules/*.mdc` |
| 加载方式 | 每次自动加载 | 动态拼装 |
| 文件格式 | `.md` | 推荐 `.mdc`（带 frontmatter） |
| 注入时机 | Session 启动时 | 根据设置（Always apply 或手动） |

> [!note]
> **plan.md 和 CLAUDE.md 的关系**
> `plan.md` → 抽取长期规则 → `CLAUDE.md`
>
> Plan Mode 生成的计划文档中，长期有效的规则应该沉淀到 CLAUDE.md 中。

## 规则文件的维护与更新

项目开发很长时间后，`CLAUDE.md` 需要更新。**官方推荐的做法不是简单重写，而是增量维护和更新**。

> [!tip]
> **CLAUDE.md 的更新方式**
> - 使用 `/init` 来生成或刷新模板（利用 Cursor 里面开启 max mode 来更新）
> - 手动编辑 CLAUDE.md
> - 在对话中让 Claude/Cursor 帮你更新（更细粒度、更贴合当前需求）

第三种方式（在对话中更新）相比重新运行 `/init` 更灵活，因为它可以基于当前的具体需求进行定向修改，而不是重新生成整个文件。

## 自动压缩：compact 与 summarize

当对话越来越长，接近 token 上限时，Claude Code 会自动执行 **compact（压缩）** 操作。

### compact vs summarize

> [!warning]
> **compact 和 summarize 不一样**
> - `summarize`（生成摘要）：直接从对话/计划/代码推导出一个可读的 summary 文本，强调**人能理解**
> - `compact`（压缩上下文）：在内部做上下文融合，将历史信息压缩成更紧凑的 token 形式，强调**减少 token 量、维持语义连续**

### auto-compact 的触发机制

> [!info]
> **auto-compact 执行流程**
> 1. 当上下文接近 token 上限时自动触发
> 2. 生成一个 summary
> 3. 在内部重建一个新的上下文窗口
> 4. 用这个 summary 作为起点继续推理

从用户视角看，会话是连续的——终端窗口没变，session id 没换，历史记录还能滚动看。但从模型视角看，这是一个**全新的上下文窗口**，模型看到的是 `[summary + 新消息]`，旧上下文已经被丢弃。

> [!success]
> **超简总结**
> `compact = 新的 context window + 老的 session id`

### compact 斜杠命令

Claude Code 还提供了 `/compact` 斜杠命令，用于手动触发压缩操作。但**不需要经常手动触发**——它会自动触发，普通开发者一般不用手动操作。

```bash
# /compact 命令的作用
# 把历史对话和重要信息抽象成更紧凑的、可持续追踪的 summary
```

## 总结

规则文件系统和自动压缩机制，共同构成了一个可持续的 AI 工作流：

- **规则文件**确保 AI 持续遵守项目规范
- **自动压缩**确保上下文不会无限膨胀
- **增量维护**确保规则文件随着项目演进而更新

掌握这些机制，你就能建立一个真正可持续的 AI 辅助开发工作流，而不是每次都要从头解释项目背景和规范。
