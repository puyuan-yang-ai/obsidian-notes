# 从想法到代码：Plan Mode 的正确打开方式

在 AI 辅助编程的实践中，许多开发者容易陷入一个误区：把 AI 当作"立刻写代码的工具"，有什么想法就直接让 AI 开始动手。这种做法看似高效，实则常常导致方向偏差、反复返工。真正高效的实践是将 AI 定位为"**联合设计者 + 执行者**"，让它先参与需求梳理和方案设计，最后才进入代码实现阶段。而这正是 Plan Mode 的核心价值所在。

## Plan Mode 的本质：先分析，再执行

> [!info]
> **Plan Mode 的核心机制**
> - 通过只读方式（分析代码库、阅读文档）来理解需求
> - 生成详细的执行计划文档
> - 等待用户确认后再执行代码改动
> - 简言之：先分析并制定计划，不直接修改代码

无论是 Claude Code 还是 Cursor，Plan Mode 的设计逻辑都是一致的：**将"模糊想法"先转化为"需求文档"，再转化为"可执行计划方案"**。这个两步转化的过程，本质上是对需求进行反复打磨和澄清，确保后续的代码执行不会因为需求不清晰而走弯路。

## 推荐工作流程：三步走策略

使用 AI 编程工具时，推荐采用以下工作流程：

```bash
# 第一步：进入 Plan Mode，把需求贴进来
# 让 AI 先做大范围的分析和方案草拟

# 第二步：多轮对话完善计划
# 反复确认细节、约束、优先级
# 避免中途发现方向不对

# 第三步：确认计划后切回默认/自动编辑模式
# 让 AI 按 Plan 文档执行代码编写
```

### 在 Cursor 中的实践

Cursor 的工作流程可以进一步细化为：**Ask 模式 → Plan Mode → 执行**。

> [!tip]
> **Ask 模式的目标**
> - 多轮澄清需求
> - 对齐目标
> - 明确约束
> - 消除歧义

许多资深开发者认为，**先在 Ask 模式来回几轮澄清，再让 Plan Mode 执行**，比"一上来就 Plan"更稳。当需求和细节都已经敲定、没有歧义时，再进入 Plan Mode，让它把"已经明确的需求"翻译成"工程执行方案"。

### 在 vibe coding 中的实践

vibe coding 采用了文档驱动的方案：将想法写入 `task.md`，让 AI 根据 `task.md` 复述并提出问题与用户对齐，进一步完善 `task.md`，最后基于 `task.md` 生成 `plan.md` 项目方案文档。

> [!note]
> **文档驱动的工作流**
> - `todo.md`：存放新思考和想法，以及后续要开发的新功能
> - `task.md`：经过多轮对话打磨后的需求文档
> - `plan.md`：基于 task.md 生成的可执行工程方案

## Plan Mode 的产物：可编辑的 Markdown

Plan Mode 生成的不是临时对话，而是一个 **Markdown 文档**。这意味着：

1. 它是可以编辑的——你可以添加更多细节、去掉不需要的步骤、重新排序任务优先级
2. 它是可以保存的——作为项目的一部分 commit 到仓库
3. 它可以作为 **Specification**——成为团队的共享知识资产

> [!success]
> **Plan Mode 的真正价值**
> - 把 AI 的思路变成你自己也能确认的实施计划
> - 让整个开发过程可追溯、可审查
> - 便于团队协作和知识传承

## Auto-Accept Mode：快速推进的双刃剑

在讨论 Plan Mode 时，不得不提 Auto-Accept Mode（自动接受模式）。这是一种让 AI 自动执行建议的更改而不弹出每一步确认的模式。

> [!danger]
> **Auto-Accept Mode 何时不应使用**
> - 第一次在陌生项目改代码时
> - 担心误删/误改重要文件时
> - 想要人工过滤每一条更改时

需要区分的是 **Auto-Accept Mode** 和 **YOLO 模式**：

- **Auto-Accept Mode**：仅针对文件修改不弹确认，工具调用/系统权限仍要确认
- **YOLO 模式**：几乎完全绕过所有权限提示，包括 shell 命令执行、工具调用等

Auto-Accept Mode 只自动接受文件编辑类操作，涉及工具调用和系统权限仍需要确认；而 YOLO 模式会跳过几乎所有权限确认，使整个流程全自动执行，**风险极高**，仅适合 CI/脚本自动化场景。

## 总结

Plan Mode 的核心价值在于：**把代码执行前的思考过程显性化、可审查化**。它不是让你放弃思考，而是帮助你更有序、更全面地思考。

当你掌握了 Plan Mode 的正确打开方式，AI 就不再是一个"会写代码的黑盒"，而是一个可以与你深度协作的"联合设计者 + 执行者"。
