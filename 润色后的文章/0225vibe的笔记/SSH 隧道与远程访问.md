# SSH 隧道与远程访问

当 OpenClaw 的 Dashboard 运行在远程 VPS 上时，如何安全地访问它？SSH 隧道是最推荐的方案。本文详细介绍 SSH 隧道的原理和配置方法。

## 理解 localhost 与 127.0.0.1

### 基本概念

- **localhost**：域名（Hostname），就像 `google.com`
- **127.0.0.1**：具体的 IPv4 地址

在 `/etc/hosts` 文件中通常有：

```
127.0.0.1 localhost
```

这告诉系统：看到 `localhost` 就解析到 `127.0.0.1`。

### 核心理解：127.0.0.1 = 我自己

无论 Windows、Linux、Mac、服务器、树莓派、Docker 容器：

> **127.0.0.1 永远指向当前这台机器自己**

### 为什么不同机器上 127.0.0.1 指向不同却不矛盾？

因为 127.0.0.1 不是"网络地址"，而是**每台机器内部的专用地址**。

比喻：每栋楼都有前台电话 1000
- A 楼打 1000 → A 楼前台
- B 楼打 1000 → B 楼前台
- 不会串

127.0.0.1 就是每台机器的"内部专线"。

## SSH 隧道原理

### 什么是 SSH 隧道

比喻：**在本地开个假门，门后面连着远程机器**

专业术语：Port Forwarding / SSH Tunnel / Local Proxy

### 本地端口转发语法

```bash
ssh -L [本地端口]:[远程主机]:[远程端口] 服务器
```

### 参数详解

以 `-L 18789:127.0.0.1:18789` 为例：

| 部分 | 含义 |
|------|------|
| 第一个数字 | 本地端口（你电脑上监听的端口） |
| 中间地址 | 远程目标主机（服务器视角下的地址） |
| 最后数字 | 远程目标端口（服务器上的端口） |

> [!tip]
> 中间的 `127.0.0.1` 是**服务器视角下的**本机地址，不是你电脑的地址。

### 完整流程

```
你的浏览器 → 本地 18789 端口 → SSH 隧道 → 远程服务器 127.0.0.1:18789 → openclaw-gateway 服务
```

### 示例

```bash
# 本地 8080 转发到远程 80 端口
ssh -L 8080:127.0.0.1:80 user@server
```

## SSH Config 配置

### 使用别名简化连接

在 `~/.ssh/config` 中配置：

```
Host aliyun-sg
    HostName 实际IP
    User root
    LocalForward 18789 127.0.0.1:18789
```

之后只需 `ssh aliyun-sg` 即可连接并建立隧道。

### LocalForward 指令

LocalForward 是 SSH 客户端配置文件中的指令，作用是**把本地端口通过 SSH 隧道转发到远程服务器端口**。

### 与 SSH 隧道的关系

LocalForward 是实现 SSH 隧道最常用的技术手段，就像"顺丰快递"和"物流运输"的关系。

## 访问 OpenClaw Dashboard

### Dashboard URL 结构

`openclaw gateway status` 显示类似：

```
Dashboard: http://127.0.0.1:18789/33c9e8d7/
```

- `33c9e8d7` 是自动生成的 **dashboard token path**
- 作用：防止别人直接访问
- 直接访问 `/` 会返回 Not Found

### 安全建议

> [!danger]
> **不要把 18789 端口暴露到公网！**

正确做法是通过 SSH 隧道访问：

1. 建立 SSH 隧道
2. 在本地浏览器访问 `http://127.0.0.1:18789/33c9e8d7/`

## 总结：SSH 隧道的本质

> **把远程服务"假装成本地服务"**

你访问 `127.0.0.1:18789`，感觉像本机程序，其实跑在远程服务器。这就是 SSH 隧道的魔力——安全、简单、无需暴露端口到公网。
