# SFT 训练实战：数据量、过拟合与工具选择

在监督微调（SFT）的实际操作中，如何根据数据量选择合适的 epoch 数、如何防止过拟合、以及如何选择合适的训练工具，是每个深度学习从业者必须掌握的实战技能。本文将系统梳理这些关键问题，为你的 SFT 训练提供实用指南。

## 数据量与 epoch 的权衡

很多初学者会困惑："数据量少时应增加 epoch 让模型多看几遍"这个建议是否矛盾——样本少 + 学习次数多，不是更容易过拟合吗？

这个质疑是完全正确的！这确实是一个需要权衡的问题：

- **数据太少 + epoch 太少** → 模型学不到东西（欠拟合）
- **数据太少 + epoch 太多** → 模型死记硬背（过拟合）

正确的理解是：**数据量少时需适度增加 epoch（比如从 1 → 3），但绝不是越多越好，必须搭配其他防过拟合手段。**

### 不同数据量下的推荐 epoch 范围

| 数据量 | 推荐 epoch | 注意事项 |
|--------|-----------|----------|
| < 500 条 | 5-10 | 必须搭配低 lr + 高 dropout + 监控 eval loss |
| 500-5000 条 | 3-5 | 观察 loss 曲线灵活调整 |
| 5000-50000 条 | 2-3 | 通常 3 epoch 足够 |
| > 50000 条 | 1-2 | 数据充足，1 epoch 也能学到很多 |

> [!danger]
> **小数据集训练的黄金法则**：
> epoch 数只是其中一个因素，必须配合学习率、正则化、dropout 等综合手段，并且**务必监控 eval loss**，一旦出现 train loss 持续下降但 eval loss 开始上升的情况，立即停止训练。

## 防过拟合的配套措施

在 SFT 训练中，防止过拟合不能只靠减少 epoch，需要一套综合策略：

### 1. 降低学习率
将学习率从 2e-4 降低到 5e-5，减小参数更新的步长，让模型学习更加"保守"。

### 2. 减少 LoRA rank
rank 越小，可训练参数越少，越不容易过拟合。例如将 rank 从 32 降低到 8。

### 3. 增加 weight decay
将 weight decay 从 0.01 增加到 0.1，对参数施加 L2 正则化，抑制权重过大。

### 4. 使用 dropout
LoRA 有 `lora_dropout` 参数，可以在训练过程中随机丢弃部分连接，增强泛化能力。

### 5. 监控 eval loss（最重要）
如果 train loss 持续下降但 eval loss 开始上升，就是过拟合的明确信号，应该立即早停（early stopping）。

> [!tip]
> **实战建议**：
> 对于小数据集（< 500 条），建议使用以下配置组合：
> - epoch: 5-7
> - learning_rate: 5e-5 或更低
> - lora_rank: 8 或 16
> - lora_dropout: 0.1
> - weight_decay: 0.05-0.1
> - 必须准备验证集，每个 epoch 结束后评估一次

## 训练指标的实时记录

在 SFT 训练过程中，Hugging Face Trainer 已经自动帮我们完成了指标记录工作。像 loss、step 等信息会存储在 `output_dir` 下的 `trainer_state.json` 文件中的 `log_history` 字段。

记录频率由 `logging_steps` 参数控制，通常设为 10-50 步（建议让总日志条目在 200-1000 条之间）。在训练监控中，除了 loss 曲线，我们还需要关注：

- **Loss 曲线**（最重要）：判断模型是否在收敛、是否过拟合
- **学习率曲线**：确认 warmup 和 decay 是否按预期执行
- **Eval loss 曲线**：对比 train loss 和 eval loss 来判断过拟合
- **Grad norm**：梯度范数，观察训练稳定性（突然飙升说明训练不稳定）
- **吞吐量（samples/s）**：监控训练效率，识别性能瓶颈

## 训练速度的评估标准

对于 Qwen-0.5B 这种小模型配合 LoRA 微调，1.2 it/s 属于中等偏慢的速度。通常在单卡 A100/A800 上可以达到 3-8 it/s。如果你的训练速度明显低于这个范围，可以考虑以下优化方向：

1. **调整 batch size 和梯度累积**：在显存允许的情况下，增大 per_device_train_batch_size，减少梯度累积步数
2. **检查数据加载**：确保数据预处理和加载不是瓶颈
3. **优化序列长度**：过长的序列会显著拖慢训练速度
4. **使用混合精度训练**：fp16 或 bf16 可以大幅提升训练速度

## 工具选择：LLaMA-Factory vs 原生框架

LLaMA-Factory 是目前中文社区最流行的 SFT 工具之一，它的核心特点包括：

1. **零代码/低代码配置**：YAML 一键启动
2. **全面的模型支持**：支持几乎所有主流模型（Qwen、LLaMA、ChatGLM、Baichuan 等）
3. **集成多种微调方式**：LoRA / QLoRA / Full / Freeze 等
4. **内置完整流程**：数据集管理、评估、推理、合并等

### 学习路径建议

对于学习和实践而言，建议采用以下路径：

- **学习阶段**：先用原生 Transformers + PEFT 手写训练脚本，深入理解每个参数的含义和作用机制
- **实践阶段**：之后再迁移到 LLaMA-Factory，此时你会清楚它帮你封装了什么，遇到问题也能快速定位和解决

> [!note]
> **工具与原理的关系**：
> LLaMA-Factory 是加速器，理解原理才是核心。工具可以提高效率，但只有深入理解底层机制，才能在遇到复杂问题时做到游刃有余。

## 文件系统与断点续训

SFT 训练完成后，输出目录中会包含两类文件夹：

- **checkpoint-9762/**：包含完整的训练状态，用于断点续训（resume training）。包括 adapter_model.safetensors、adapter_config.json、optimizer.pt、scheduler.pt、trainer_state.json、training_args.bin、rng_state.pth 等
- **final/**：只保留推理所需文件，不含优化器、调度器、随机数、训练状态等，专为推理部署设计

两者的文件数量差异源于设计目标的不同：checkpoint 是为了能够从中断点恢复训练，需要保存完整的训练状态；而 final 是为了推理部署，只保留模型权重和配置信息。

## 实战检查清单

在开始 SFT 训练之前，建议对照以下检查清单：

```bash
# 1. 数据准备
- [ ] 数据格式正确（JSON/JSONL，包含 instruction、input、output 字段）
- [ ] 数据质量检查（无明显噪声和错误）
- [ ] 数据量级确认（< 500 / 500-5000 / 5000-50000 / > 50000）
- [ ] 验证集准备（至少准备 10-20% 作为验证集）

# 2. 超参数设置
- [ ] 根据数据量选择合适的 epoch 数
- [ ] 设置合理的学习率峰值（小模型 2e-4，大模型 1e-4）
- [ ] 配置 warmup steps（通常为总步数的 3-10%）
- [ ] 选择合适的 batch size 和梯度累积步数
- [ ] 设置防过拟合措施（dropout、weight decay）

# 3. 训练监控
- [ ] 配置 logging_steps（建议 10-50）
- [ ] 设置 eval_steps 和 save_steps
- [ ] 准备好监控工具（TensorBoard / WandB）

# 4. 训练执行
- [ ] 启动训练
- [ ] 实时监控 loss 曲线
- [ ] 观察梯度范数和训练速度
- [ ] 定期检查 eval loss，识别过拟合迹象
```

通过系统化的准备和监控，你的 SFT 训练将更加稳定和高效。记住：**数据量、epoch、学习率、正则化是一个整体，需要综合考虑和动态调整**。
