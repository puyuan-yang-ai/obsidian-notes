# SFT 实践与优化技术

在实际应用中，SFT（监督微调）不仅仅是理论上的训练流程，更是一系列工程实践和优化技术的综合。从 Trainer 的执行流程到 LoRA 的高效参数更新，从训练策略的选择到开发环境的配置，每一个细节都会影响最终的模型效果。

## Trainer：训练的执行引擎

在 SFT 的完整结构中，Trainer 是最后也是最关键的环节。整个流程如下：

```
dataset → tokenizer → model → trainer → SFT model
```

**Trainer 的执行流程**可以概括为五个步骤：

1. **Batch**：从数据集中采样一个批次的数据
2. **Forward**：前向传播，计算模型输出
3. **Loss**：计算损失函数
4. **Backward**：反向传播，计算梯度
5. **Update weights**：更新模型权重

这个流程不断循环，直到满足停止条件。理解这个流程，有助于我们在实践中调试和优化训练过程。

## LoRA：解决显存爆炸的优雅方案

如果不使用任何优化技术，直接对一个 Qwen-7B 模型进行 SFT 会发生什么？

Qwen-7B 的参数量约为 70 亿。如果不使用 LoRA，训练时需要更新全部 70 亿参数，这会带来三个严重问题：

1. **显存爆炸**：需要存储所有参数的梯度
2. **训练很慢**：参数太多，计算量巨大
3. **成本高**：需要大量 GPU 资源

**LoRA（Low-Rank Adaptation）** 提供了一个优雅的解决方案。它的核心思想是：**冻结原模型，只训练一个小矩阵**。

具体做法如下：

原来的权重矩阵是 `W`，LoRA 在其基础上加了两个小矩阵 `A` 和 `B`，实际计算变成：

```
W + A × B
```

其中：
- `A` 的维度：`d × r`
- `B` 的维度：`r × d`
- `r` 是一个很小的数，比如 `r = 8`

需要训练的参数从原来的 **70 亿**直接降到**几百万**，显存使用量直接下降几十倍。

### LoRA 的训练流程

LoRA 的做法与传统微调完全不同：

1. **冻结 W**：原模型的权重不更新
2. **新增 A、B**：两个小矩阵
3. **训练时更新**：只更新 A 和 B，而不是 W
4. **最终得到**：LoRA adapter

可以总结为：**freeze model + train adapter**。

> [!tip]
> **LoRA 的优势**：
> - 大幅降低显存需求
> - 训练速度更快
> - 可以针对不同任务训练多个 adapter，快速切换
> - 原模型保持不变，便于共享和管理

这种技术让普通开发者也能在消费级 GPU 上微调大模型，极大降低了 SFT 的门槛。关于 LoRA 的更多细节，可以参考 [[LoRA 原理与实践]]。

## 训练策略：何时停止训练？

在实践中，一个常见的误区是：**训练步数越多越好**。但事实并非如此。

判断是否应该停止训练，主要看三件事：

### 1. 训练集 loss 是否还在下降

- 如果 loss 还明显下降，说明模型还在学习
- 如果 loss 降得很慢、基本不变或开始震荡，说明继续训练的收益在变小

### 2. 验证集指标有没有变好（最关键）

训练集 loss 下降并不代表模型真的变好了，可能只是记住了训练数据，开始过拟合。

更应该关注：
- **Eval loss**：验证集上的损失
- **Few-shot 测试**：抽样测试生成质量

这是判断模型是否真正提升的最可靠指标。

### 3. 生成效果是否已经达到目标

SFT 是一个非常工程化的过程，最终还是要看实际效果。

比如你只想让模型学会某种格式、某种领域问答风格，当它已经能稳定输出你想要的效果时，就可以停止训练。

> [!info]
> **训练策略的核心**：
> 不是盲目追求更多的训练步数，而是在训练集表现、验证集泛化和实际生成效果之间找到平衡点。

## 控制训练时长的参数

在代码中，通常有两个参数控制"训练多久"：

### 1. `max_steps`

直接控制最多训练多少步。

```python
max_steps = 3000  # 训练到 3000 step 就停
```

### 2. `num_train_epochs`

控制训练几个 epoch（完整遍历数据集的次数）。

```python
num_train_epochs = 3  # 把整个训练集跑 3 遍
```

### 优先级关系

如果同时设置了 `max_steps` 和 `num_train_epochs`，`max_steps` 的优先级往往更高。也就是说，**到了最大 step 就先停**。

在实践中，推荐使用 `max_steps` 来精确控制训练时长，同时结合验证集指标动态调整。

## 开发环境配置：Cursor 终端字体调整

在日常开发中，一个舒适的开发环境至关重要。Cursor 里的终端字体默认可能较小，可以通过以下方式调整：

1. 按 `Ctrl + Shift + P` 打开命令面板
2. 输入 "Open User Settings (JSON)" 并回车
3. 添加以下配置：

```json
"terminal.integrated.fontSize": 16
```

保存后，终端字体会立即生效。

> [!note]
> 这个配置也可以用于调整编辑器的其他 UI 元素，比如 `editor.fontSize`、`debug.console.fontSize` 等。

## 实践建议

基于以上内容，以下是一些实践中的建议：

1. **从小模型开始**：使用 TinyLlama 或 Qwen small 模型快速验证流程
2. **使用 LoRA**：除非有特殊需求，否则总是使用 LoRA 进行微调
3. **关注验证集**：不要只看训练 loss，验证集指标才是关键
4. **早期停止**：设置合理的早停策略，避免过拟合
5. **记录实验**：保存每次实验的配置和结果，便于对比和复现

SFT 是一个高度实践性的领域，理论知识固然重要，但只有通过大量的实验和调试，才能真正掌握其中的技巧和经验。
