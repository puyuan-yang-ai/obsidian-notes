# Git 核心概念与基础工作流

## Git 的三区模型

理解 Git 的核心在于掌握其**三区模型**：工作区（Working Directory）、暂存区（Staging Area）和本地仓库（Local Repository）。这三个区域构成了 Git 版本控制的基础架构，数据在其间的流动形成了我们日常的开发工作流。

```bash
工作区 --[git add]--> 暂存区 --[git commit]--> 本地仓库
```

当我们修改代码后，更改首先存在于**工作区**。要将这些更改纳入版本控制，第一步是使用 `git add` 命令将更改添加到**暂存区**（也称为 staging area）。暂存区是一个准备区域，允许我们有选择地决定哪些更改将被提交。最后，使用 `git commit` 命令将暂存区的内容正式提交到**本地仓库**，形成一个永久的版本快照。

> [!info]
> **暂存区的英文名称**
> - Staging Area 是最常用的术语
- Index 是其技术实现名称
- 两者指的是同一个概念

## .git 目录：Git 的大脑

如果说暂存区是 Git 的"候车室"，那么 `.git` 目录就是 Git 的"大脑"。这个默认隐藏的目录是 Git 跟踪和管理项目版本控制信息的**核心存储区**。当我们执行 `git init` 命令初始化仓库时，Git 做的唯一事情就是创建这个 `.git` 目录。

`.git` 目录包含了完整的版本控制信息：提交历史、分支引用、标签、配置信息等。它管理着项目的不同版本和各个分支，并记录所有的提交历史。如果一个项目没有 `.git` 目录，说明这个项目没有被 Git 版本控制系统管理。若要永久移除项目的 Git 版本控制，只需删除这个目录即可。

> [!warning]
> **删除 .git 目录的后果**
> - 所有版本控制历史将永久丢失
- 项目将变为普通的文件夹
- 此操作不可逆，请谨慎执行

## 查看与比较更改

在开发过程中，我们经常需要查看当前做了哪些修改。`git status` 命令显示工作区和暂存区的状态，包括哪些文件被修改、哪些修改已被暂存等信息。

> [!tip]
> **在 IDE 中调出 Git 操作的快捷键**
> - WebStorm/IntelliJ IDEA：`Alt + ~`（波浪号，位于键盘左上角）
> - PyCharm 查看分支信息：`Alt + 9`

当我们想对比相对于上次提交有哪些新的改变时，应该使用 `git diff` 命令（或在 IDE 中点击 "Show Diff"）。这个命令显示**当前工作区与上次提交之间的差异**，用于展示自上次提交以来对文件所做的未提交改动。

## Stash：暂存之外的临时存储

很多初学者会混淆暂存区（Staging Area）和 Stash 这两个概念，但它们服务于完全不同的目的。

暂存区用于**准备即将提交的更改**，是正常提交流程的一部分。而 Stash（`git stash` 命令）则用于**临时保存未完成的工作**，允许你将当前的工作进度存储到一个独立的 stash 区域，稍后可以恢复，而不会干扰到当前的工作流程。

```bash
# 临时保存当前未完成的更改
git stash

# 恢复之前保存的更改
git stash pop
```

> [!question]
> **Stash Changes 是将更改存储到暂存区吗？**
>
> 不是。Stash 将更改存储到 Git 的一个独立 stash 区域，与暂存区完全不同。

## 在 IDE 中启用 Git 版本控制

对于使用 JetBrains 系列 IDE（如 WebStorm、PyCharm）的开发者，如果项目还没有启用 Git 版本控制，有两种方式：

1. 选择 **"Enable Version Control Integration"**，然后选择 **"Git"**
2. 直接使用 **"Add to VCS"** 选项

启用后，在 WebStorm 中点击 "commit" 按钮时，IDE 实际执行了两个操作：首先将更改添加到暂存区（相当于 `git add`），然后将暂存的更改提交到本地仓库（相当于 `git commit`）。这种自动化让工作流更加流畅。

## 基础操作命令总结

以下是日常开发中最常用的 Git 命令：

```bash
# 将文件添加到暂存区
git add .

# 提交更改到本地仓库
git commit -m "提交消息"

# 查看工作区和暂存区状态
git status

# 查看工作区与上次提交的差异
git diff
```
