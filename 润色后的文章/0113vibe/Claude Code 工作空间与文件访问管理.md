# Claude Code 工作空间与文件访问管理

## 概述

Claude Code 的工作空间管理是其核心功能之一。默认情况下，Claude Code 只能访问当前启动的工作目录及其子目录。然而在实际开发中，我们经常需要处理跨多个目录的项目，比如 monorepo 结构、前后端分离项目、共享库等场景。这时候就需要理解如何正确扩展 Claude Code 的工作范围，以及文件访问的各种细节规则。

## 使用 /add-dir 扩展工作空间

`/add-dir` 是 Claude Code 提供的一个斜杠命令，用于添加额外的工作目录。执行该命令后，Claude 会将指定的目录添加到当前会话的"可访问范围"中，使其能够读取和操作该目录下的文件。

> [!tip]
> **使用场景**
> - Monorepo 项目：包含 `/frontend`、`/backend`、`/shared-lib` 等模块
> - 前后端分离项目：前端和后端代码位于不同目录
> - 共享库引用：需要访问项目外的公共组件库

例如，如果在 `/frontend` 目录下启动了 Claude Code，想要访问后端模块和共享库，可以执行：

```bash
/add-dir ../backend
/add-dir ../shared-lib
```

`/add-dir` 支持两种路径格式：绝对路径（如 `/Users/.../code/lib`）和相对路径。相对路径是相对于当前启动命令所在目录的路径，使用时需要注意当前工作目录的位置。

> [!info]
> **核心作用总结**
> `/add-dir` 的本质是扩展 Claude Code 的工作空间范围，让它可以访问除当前目录以外的其他文件夹内容。这就像给 Claude Code 颁发了一张"多区域通行证"，使其能够在多个目录之间自由穿梭。

## .gitignore 与文件访问的微妙关系

一个常见的困惑是：为什么输入 `@logs/` 时不出现候选项？原因在于 `logs` 目录被列在了 `.gitignore` 文件中。被 `.gitignore` 忽略的文件不会在 Claude Code 的自动文件路径补全建议中出现。

但这引发了一个重要问题：`@logs` 没有出现在自动补全中，如果手动写 `@logs/aa.log` 会怎样？

答案可能让你意外：**Claude Code 仍然可以读取该文件**。

> [!success]
> **关键结论**
> `.gitignore` 只影响自动补全提示，不会阻止 Claude Code 读取文件内容。只要明确指定路径，即使文件在 `.gitignore` 中，Claude Code 依然可以正常访问。

这意味着 `.gitignore` 的作用是控制"可见性"而非"访问权限"——它阻止自动提示和被默认索引，但不影响手动指定路径时的文件读取。

## 快捷键与模式切换

Claude Code 提供了丰富的快捷键来提升开发效率，其中两个尤为常用：

### Meta + T：深度思考模式

提示"Use meta+t to toggle thinking"中的 `meta` 指的是特殊修饰键：
- **macOS**：⌘ Command 键
- **Windows**：Alt 键（多数情况）或 Windows 键

> [!warning]
> **重要区分**
> `Alt + T` 控制的不是"是否显示思维链"，而是是否让模型进入"深度思考模式（Extended Thinking）"。这是两个完全不同的概念。

### Shift + Tab：三种模式循环切换

`Shift + Tab` 可以在三种模式之间循环切换：

1. **默认模式**：提示需要确认，不会自动执行更改，适合需要逐步确认的安全操作
2. **自动接受模式**：不弹确认直接执行，会自动执行更改，适合信任 Claude 的情形
3. **计划模式**：先生成计划和步骤列表，不会执行变更，用于设计或规划复杂任务

> [!note]
> **模式选择建议**
> - 探索性工作：使用默认模式，保持控制权
> - 重复性任务：使用自动接受模式，提升效率
> - 复杂重构：使用计划模式，先设计后执行

## 常见误区辨析

### /add-context 是官方命令吗？

Claude Code 的 Slash Command 列表中**不存在** `/add-context` 命令，正确的是 `/add-dir`。这个命名错误可能是由于思维惯性导致的——许多工具有类似的 "add context" 概念，但 Claude Code 使用的是 "add directory" 的语义。

### 为什么新添加的自定义命令看不到？

Claude Code 的斜杠命令加载机制是**只在会话启动时扫描一次命令目录**。启动时会扫描项目中的 `.claude/commands/` 和全局命令目录，建立命令列表，之后就不会再热加载了。

因此，如果添加了新的自定义斜杠命令，需要重启 Claude Code 会话才能生效。

## 总结

掌握 Claude Code 的工作空间和文件访问管理，是高效使用这个工具的基础。核心要点包括：

1. 使用 `/add-dir` 扩展工作范围，支持多目录项目开发
2. 理解 `.gitignore` 只影响自动补全，不阻止文件访问
3. 熟练使用快捷键切换模式，根据场景选择合适的工作模式
4. 记住命令名称和加载机制，避免陷入常见误区

这些知识点相互关联，共同构成了 Claude Code 文件访问系统的完整图景。在实际使用中，根据项目结构灵活运用 `/add-dir`，结合模式切换快捷键，可以显著提升开发效率。
