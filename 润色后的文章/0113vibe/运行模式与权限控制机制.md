# 运行模式与权限控制机制

## 概述

在 Claude Code 中，理解运行模式和权限控制机制至关重要。这不仅仅关乎使用体验，更直接影响到开发效率和安全性。Claude Code 提供了多种运行模式，每种模式都有其特定的权限检查行为和使用场景。混淆这些概念可能导致意外的操作结果，甚至带来安全风险。

## Auto-Accept 模式与 YOLO 模式的本质区别

许多用户容易混淆 Auto-Accept 模式和 YOLO 模式，认为它们都是"自动执行"的变体。实际上，这两种模式在设计理念和权限控制上存在根本差异。

### Auto-Accept：UI 级别的确认简化

Auto-Accept 模式是通过 `Shift + Tab` 快捷键切换的，它的作用是**取消 UI 级别的"每次确认这个 edit 是否执行"的提示**。在这种模式下：

- 编辑提议会自动通过，无需手动确认
- 仍有可能在做危险操作之前询问权限
- 不会自动跳过所有权限检查

可以把 Auto-Accept 模式理解为"允许 Claude 自己点确认按钮"。你依然信任 Claude 的判断，但系统的安全检查机制依然存在。

### YOLO 模式：完全绕过权限系统

YOLO 模式（You Only Live Once）是真正意义上的无人值守运行。启动时需要使用 `--dangerously-skip-permissions` 这个 flag：

```bash
claude-code --dangerously-skip-permissions
```

在这种模式下：

- 所有操作都会直接执行，无需确认
- 不会限制危险操作（风险更高）
- 甚至不会在底层权限检查时弹出任何提示

YOLO 模式等同于"Claude 自动批准一切权限请求，而不会弹提示"。它不仅仅是简化 UI 确认，而是**完全关闭了核心权限系统的检查机制**。

> [!danger]
> **安全警告**
> YOLO 模式应该谨慎使用。它相当于给了 Claude Code 完全的"无人值守执行权"，包括文件改写、Bash 命令执行、系统操作等。只应该在完全信任的环境和脚本化场景中使用。

## 权限检查的层次结构

要深入理解这两种模式，需要认识 Claude Code 权限检查的层次结构：

```
┌─────────────────────────────────────────┐
│          用户操作层（UI 确认）           │
│  ← Auto-Accept 跳过这一层                │
├─────────────────────────────────────────┤
│       工具调用权限层（工具级检查）        │
│  ← YOLO 模式跳过这一层                   │
├─────────────────────────────────────────┤
│      底层系统权限层（文件/Bash 等）       │
│  ← YOLO 模式也跳过这一层                  │
└─────────────────────────────────────────┘
```

Auto-Accept 只是简化了最上层的 UI 确认流程，而下两层的安全检查依然有效。YOLO 模式则是直接穿透所有权限层，让 Claude Code 可以无障碍地执行任何操作。

> [!info]
> **类比理解**
> - **Auto-Accept**：你授权助理可以自己签字批准常规文件
> - **YOLO 模式**：你给了助理一张空白签字的授权书，包括出售资产、大额转账等一切操作

## 使用场景建议

### 何时使用 Auto-Accept 模式

适合在以下场景启用 Auto-Accept 模式：

- **重复性编码任务**：比如批量重命名变量、统一修改代码风格
- **信任的开发环境**：在本地开发环境中，信任 Claude 的判断
- **快速原型开发**：需要快速迭代，不希望被频繁确认打断

> [!tip]
> **快捷操作**
> 使用 `Shift + Tab` 可以快速切换 Auto-Accept 模式，无需重启会话。

### 何时使用 YOLO 模式

YOLO 模式适用场景更加有限：

- **CI/CD 脚本**：在自动化流程中，需要 Claude Code 执行固定任务
- **完全隔离的环境**：在容器或虚拟机中运行，即使出错也不会影响主系统
- **批处理任务**：需要处理大量文件，不希望任何交互打断

> [!warning]
> **重要提醒**
> 不要在日常开发中使用 YOLO 模式。一次错误的操作可能导致不可逆的损失，比如误删重要文件、执行危险的 Bash 命令等。

## 自定义斜杠命令的加载机制

与权限控制相关的一个知识点是自定义斜杠命令的加载机制。许多用户添加了新的自定义命令后，发现当前会话中无法使用，这是由于 Claude Code 的命令加载机制导致的。

Claude Code 的斜杠命令加载是**只在会话启动时扫描一次**：

1. 启动时扫描 `.claude/commands/` 目录
2. 扫描全局命令目录（如果配置了）
3. 建立命令列表，之后不再热加载

> [!note]
> **解决方案**
> 添加新的自定义斜杠命令后，需要重启 Claude Code 会话才能生效。这是一个常见但容易被忽视的细节。

## 权限模式的对比总结

| 特性 | 默认模式 | Auto-Accept 模式 | YOLO 模式 |
|------|----------|------------------|-----------|
| UI 确认提示 | 需要 | 不需要 | 不需要 |
| 工具权限检查 | 有效 | 有效 | 绕过 |
| 底层系统权限检查 | 有效 | 有效 | 绕过 |
| 危险操作保护 | 有效 | 部分有效 | 无保护 |
| 适用场景 | 常规开发 | 信任环境、重复任务 | 自动化脚本 |

---

## 总结

Claude Code 的运行模式和权限控制机制设计精巧，需要仔细理解其层次结构：

- **Auto-Accept 模式**只是 UI 级别的确认简化，核心权限检查依然有效
- **YOLO 模式**是完全绕过权限系统，适用于无人值守的自动化场景
- 两种模式不应混淆，错误的选择可能导致安全风险

在实际使用中，建议从默认模式开始，根据信任程度和任务需求逐步调整。对于大多数开发场景，Auto-Accept 模式是安全和效率的最佳平衡点；而 YOLO 模式应该被视为"高级用户工具"，只在明确理解其风险的情况下使用。

理解这些机制后，你可以更灵活地配置 Claude Code，在保持安全的同时最大化开发效率。
