# 训练监控与参数调优

## 核心训练指标

在模型训练过程中，有三个核心指标需要持续关注：

### Step（训练步数）

Step 表示当前训练到第几步，每一步代表模型参数更新一次。这是衡量训练进度最基本的单位。

### Epoch（数据轮次）

Epoch 表示数据集过了几遍。例如，0.13 epoch 表示整个数据集才过了 13%。完整的训练通常需要多个 epoch。

### Loss（损失函数）

Loss 是最核心的指标，衡量模型预测和正确答案之间的差距。需要注意的是，loss 不会平滑下降，短期内会上下跳动，因此要看整体趋势，通常需要画平滑曲线来观察。

> [!info]
> **Loss 判断的相对性**：
> - 不能用固定数字（如 1.5）来判断训练好坏
> - Loss 的绝对值取决于词表大小、数据质量、模型大小等因素
> - 更可靠的判断方法是看趋势：loss 曲线变平说明继续训练收益不大；eval_loss 开始上升说明过拟合了

## Python 库依赖体系

SFT 训练需要一组相互依赖的 Python 库，理解它们的作用和依赖关系对于调试问题很重要。

### Transformers

Transformers 是 HuggingFace 的核心库，提供：
- 模型加载（`AutoModelForCausalLM`）
- 分词器（`AutoTokenizer`）
- Trainer 训练框架

像 Qwen1.5-0.5B 这样的模型就是通过它加载的。

### Datasets

Datasets 是 HuggingFace 的数据集库，用一行代码就能从 Hub 下载数据集（如 `load_dataset("silk-road/alpaca-data-gpt4-chinese")`），并自动处理缓存、分片、格式转换。

### PEFT

PEFT（Parameter-Efficient Fine-Tuning）库提供 LoRA、QLoRA 等参数高效微调方法，核心类是 `LoraConfig`。

### TRL

TRL（Transformer Reinforcement Learning）库提供 `SFTTrainer`，封装了 SFT 训练的全部流程，包括数据格式化、tokenize、训练循环，让开发者不用自己写训练循环。

### Accelerate

Accelerate 是 HuggingFace 的分布式训练加速库，Trainer 内部依赖它来管理 GPU 设备、混合精度训练（fp16）、多卡并行。虽然不会直接 import 它，但没有它 Trainer 无法运行。

### 依赖关系图

```
trl (SFTTrainer)
  ├── transformers (Trainer)
  │     └── accelerate (GPU管理)
  ├── peft (LoRA)
  └── datasets (数据加载)
```

## 训练参数配置

### 日志与保存策略

三个关键参数控制训练过程中的日志记录和模型保存：

- `logging_steps = 10`：每 10 步记录一次 loss，这些记录会出现在 training_log.jsonl 文件中
- `save_strategy = "epoch"`：每个 epoch 结束保存一次 checkpoint
- `save_total_limit = 2`：最多保留 2 个最近的 checkpoint，旧的自动删除

> [!warning]
> **save_total_limit 的含义**：
> - 保留最近的 2 个 checkpoint，不是"表现最好的 2 个"
> - 好处是省磁盘：小模型每个 checkpoint 约 100MB，但 70B 大模型一个 checkpoint 可能几十 GB
> - 如果需要保存表现最好的模型，需要使用 `load_best_model_at_end` 参数

### 保存最佳模型

如果需要保存 loss 最低的 checkpoint，可以使用：

```python
load_best_model_at_end=True
metric_for_best_model="loss"
```

这样 Trainer 会在训练结束时自动加载 loss 最低的那个 checkpoint。

### 验证集配置

Alpaca 数据集本身没有提供单独的 test/validation split，需要手动处理：

**做法**：手动把数据集拆成 train (90%) + eval (10%)

**参数设置**：
```python
eval_strategy="steps"
eval_steps=100
load_best_model_at_end=True
metric_for_best_model="eval_loss"
```

**效果**：Trainer 每 100 步在验证集上计算一次 eval_loss，训练结束后自动加载 eval_loss 最低的那个 checkpoint。

## HuggingFace Trainer 回调机制

Trainer 回调在训练的不同阶段触发事件，允许在这些节点插入自定义逻辑。

### 常见回调方法

| 回调方法 | 触发时机 |
|---------|---------|
| `on_log` | 每 logging_steps 步 |
| `on_step_end` | 每个训练步结束 |
| `on_epoch_end` | 每个 epoch 结束 |
| `on_evaluate` | eval 结束后 |
| `on_train_end` | 训练结束 |

### 最常用的两个场景

**1. Early Stopping（提前终止）**

在 `on_evaluate` 里检查 eval_loss，如果连续 N 次 eval_loss 不下降就停止训练，防止浪费时间。

**2. Loss 异常检测**

在 `on_step_end` 里检查 loss 是否变成 NaN 或突然飙升，及时中断训练避免资源浪费。

## 数据格式转换

SFT 训练时需要将 JSON 格式数据转换为训练文本。原始数据是结构化的 JSON（包含 instruction、input、output 三个字段），转换后是一段纯文本字符串。

需要注意的是，`### 指令:` 和 `### 回答:` 不是 markdown 语法，而是自定义的分隔标记。实际上可以使用任何分隔符，例如：

```
[INST] 写一首关于春天的诗 [/INST] 春天来了，万物复苏...
```

**关键原则**：用什么分隔符不重要，重要的是训练和推理时使用同一套格式。

## train.py 的完整流程

模型 SFT 训练时 train.py 执行以下流程：

1. **加载数据集**：获取 52K 条中文"指令-回答"对
2. **Tokenizer 处理**：把文字转换为数字（模型只认识数字）
3. **加载预训练模型**：导入已经会"续写"但不会"遵循指令"的基础模型
4. **LoRA 适配**：在模型旁边加小旁路，只训练这部分参数
5. **Trainer 训练**：自动化训练循环（前向传播 → 算 loss → 反向传播 → 更新参数）

## Docker 命令使用

在使用 Docker 进行训练时，常见的命令格式：

- `docker exec sft-demo bash -c "..."`：在 sft-demo 容器里执行引号内的命令
- `docker exec -it sft-demo bash`：进入容器的交互式终端

> [!danger]
> **常见错误**：
> - `docker exec sft-demo bash` 会立即退出，因为缺少 `-it` 参数
> - `-i` = interactive（保持标准输入打开）
> - `-t` = tty（分配一个终端）
> - 没有这两个参数，bash 启动后发现没有交互终端就立刻退出
