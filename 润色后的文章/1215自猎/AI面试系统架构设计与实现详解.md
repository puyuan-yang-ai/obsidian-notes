# AI面试系统架构设计与实现详解

## 系统核心接口概览

AI面试系统通过多个精心设计的接口实现了完整的面试流程管理，每个接口都有其特定的职责和使用场景。

### 主要功能接口

- **virturlInterview接口**：模拟面试核心功能，对求职者进行实时问答，以流式方式返回AI面试官的回复
- **interviewReport接口**：面试结束后，根据对话记录、岗位信息及音视频内容，生成综合面试评估报告
- **jdFillingGenerate接口**：用于生成虚拟岗位，AI根据用户画像和期望职位自动创建公司与岗位描述
- **resumeBasicOptimize接口**：对简历的基本信息、工作经历和项目经历进行自动润色与优化
- **resumeDeepOptimize接口**：简历深度优化，基于对话历史进行针对性改进与提升

> [!warning] 虚拟岗位说明
> jdFillingGenerate接口生成的是虚拟岗位，AI会根据用户画像自动构造公司与岗位描述，但这些岗位并不真实存在，仅用于模拟面试场景。

## 简历优化系统设计

简历优化功能提供了两种不同的接口，以满足不同的使用场景：

### 基础优化与深度优化的区别

- **/resumeBasicOptimize**：进行基础润色，优化简历的基本信息、工作经历和项目经历
- **/resumeDeepOptimize**：进行深度优化，结合对话历史进行针对性改进

### 对话型与生成型接口

深度优化功能进一步细分为两个接口：

1. **/resume/deep-optimization/converse**：对话型接口，支持多轮交互
   - 首次请求时不需要携带conversation_plan
   - plan字段只在首次调用返回，后续请求必须携带该字段
   - over信号表示对话可以结束，前端收到后可调用generate接口

2. **/resume/deep-optimization/generate**：生成型接口，根据对话生成最终优化的简历

> [!tip] 接口使用流程
> 监听over信号 → 显示"生成简历"按钮 → 用户点击后调用generate接口生成简历

### 流式响应的实现

/resumeDeepOptimize接口采用流式响应，但这**不是**指"逐字输出建议"，而是"逐模块推送结果"：
- [模块1：基本信息优化结果]
- [模块2：工作经历优化结果]
- [模块3：项目经历优化结果]

使用流式响应是因为简历优化耗时较长（可能超过20秒），分块返回结果让用户边等边看，显著提升用户体验。

## 意图分类系统

系统采用智能意图分类来路由不同的请求类型。传统的意图分类需要训练专门的模型（如BERT、TextCNN），依赖大量标注数据。而本系统利用大模型的零样本能力，通过Prompt直接完成分类：

- 预设三种意图：resume_optimize、generate_job、chat
- 通过提示限定只能三选一，并用JSON格式输出
- 从intent字段读取结果进行路由处理

## 模拟面试系统的AI设计

### 多层AI架构

模拟面试采用了分层AI设计，不同面试类型有不同的处理流程：

#### 白领面试（interviewType=1）
采用**双层AI架构**：
1. **策略AI**：分析对话历史并制定回复策略
2. **执行AI**：根据策略流式生成面试官的回复
3. **判断AI**：判断面试是否应该结束

考察重点：硬技能、软技能和文化适配

#### 蓝领面试（interviewType=0）
采用**单层AI架构**：
1. **执行AI**：直接生成面试官回复
2. **判断AI**：判断面试是否应该结束

考察重点：年龄、身体状况和稳定性

> [!note] AI之间的协作关系
> 策略AI和执行AI之间是**串行的单向关系**：策略AI → 执行AI → 返回用户。执行AI的结果不会回传给策略AI。

### 面试结束的自动判断

系统通过第三个AI模型自动识别面试结束时机：
- **输入**：面试官的最新回复（ai_response）
- **处理**：AI分析是否包含结束意图
- **输出**：仅两个结果——"继续"或"结束"

判断基于语义识别而非字符串匹配，因为结束语可能有多种表达形式。

### 多轮对话的实现机制

虽然/virturlInterview接口每次只返回一次回复，但多轮对话是通过客户端实现的循环流程：
1. 调用接口获取面试官回复
2. 用户输入回答
3. 将双方对话追加到dialogHistory
4. 再次调用接口
5. 如此循环，直到面试结束

## 面试报告生成系统

### 异步报告生成

报告生成接口采用异步处理模式：
- 接口请求后立即返回`{"message": "success"}`
- 后台启动异步任务进行AI分析
- 生成完成后更新数据库并推送到外部URL

这种设计避免了HTTP请求超时，提升了用户体验。

### 报告结构解析

生成的final_report包含多个维度的分析：

```json
{
  "overall_assessment": {},      // 整体评估
  "detailed_analysis": [],       // 详细分析
  "competency_model_used": {},   // 能力模型
  "job_match_analysis": {},      // 岗位匹配分析
  "personality_analysis": {},    // 性格分析
  "salary_analysis": {},         // 薪资分析
  "style_report": {},            // 风格报告
  "user_report": {}              // 候选人报告
}
```

其中，user_report属于候选人报告；其余所有字段均为HR报告。

报告不是一次性生成的，而是通过模型多次调用生成各个子字段后，再汇总注入到final_report中。

## 技术实现细节

### 数据序列化处理

在JSON格式中，即使是数字ID通常也会用字符串表示，这是为了避免大数字精度问题。Python中的序列化和反序列化使用：

- 序列化：`json.dumps()`
- 反序列化：`json.loads()`

> [!warning] 序列化时机
- 需要序列化：发送HTTP请求、存数据库、写入文件时
- 不需要序列化：对象已是JSON字符串，或框架会自动序列化时

### 流式传输机制

流式传输包含两种类型的数据：
- **heartbeat**：状态消息，表示进度或存活状态
- **chunk**：实际内容片段

两者都通过流式方式传输，只是类型不同。

### Redis临时存储

系统使用Redis作为临时存储系统，特点包括：
- 读写速度极快，比数据库快几十倍
- 使用简单，像字典一样操作（set、get）
- 适合存储临时数据，支持设置过期时间自动清理
