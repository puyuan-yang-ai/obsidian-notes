# 任务配置与管理

在AIG-Eval框架中，任务配置与管理系统是其核心组件之一，负责定义和组织各种GPU kernel优化任务。通过精心设计的配置结构和灵活的任务管理机制，AIG-Eval能够支持多种不同类型的优化任务，为[[Agent集成与执行流程]]提供标准化的任务接口。

## 任务目录结构

AIG-Eval采用层次化的目录结构来组织任务，每个任务都有独立的配置文件和相关资源。添加新任务时，需要在tasks/目录下创建标准的文件夹结构：

```
tasks/
└── 你的类别/
    └── 你的任务名/
        ├── config.yaml     ← 任务配置（编译命令、正确性命令等）
        ├── 源代码.hip      ← 需要优化的代码
        └── Makefile        ← 构建文件
```

> [!tip] 
> 这种模块化的任务组织方式使得不同类型的GPU kernel优化任务可以独立开发和维护，大大提高了框架的可扩展性。

## 配置文件详解

每个任务的核心是其config.yaml文件，该文件定义了任务执行所需的所有关键信息：

### 核心配置字段

- **source_file_path** - 指定Agent需要优化的源代码文件路径
- **compile_command** - 定义编译代码的具体命令
- **correctness_command** - 设置验证优化后代码正确性的测试命令
- **performance_command** - 配置测量性能的基准测试命令
- **task_type** - 指定任务类型，如hip2hip等

### 配置示例分析

以silu任务为例，其config.yaml可能包含如下内容：

```yaml
source_file_path:
  - silu.hip              # 【源文件】
compile_command:
  - make                  # 【编译命令】
correctness_command:
  - ./test                # 【正确性验证命令】
performance_command:
  - ./benchmark           # 【性能测试命令】
task_type: hip2hip        # 【任务类型】
```

这些配置字段共同构成了任务的执行规范，框架会读取这些信息并将其作为提示词的一部分传递给Agent。

## 任务执行机制

### 测试流程设计

AIG-Eval的任务执行机制体现了其独特的设计理念。框架本身并不直接处理文件或执行具体的测试逻辑，而是：

1. 读取任务的config.yaml文件
2. 将配置信息传递给Agent作为prompt的一部分
3. 让Agent自主决定如何执行各个步骤

> [!warning] 
> 这种设计与传统脚本化测试有本质区别。框架不告诉Agent"怎么做"，只告诉它"要做什么"。

### 不确定性处理

由于AI Agent生成结果的随机性，同样的任务和Agent可能导致不同的执行流程。AIG-Eval通过以下策略应对这种不确定性：

- **多次运行取统计值** - 同一个Agent+同一个Task运行多次（如5次）
- **统计指标多样化** - 计算平均分、成功率、最高分等多个维度
- **评分维度固定** - 无论过程如何，最终都按统一标准评分

### 评分标准一致性

尽管执行过程可能不同，但最终评分维度始终固定：
- ✅ 编译通过了吗？ → pass_compilation: true/false
- ✅ 正确性验证通过了吗？ → pass_correctness: true/false
- ✅ 性能加速了多少？ → speedup_ratio: 1.5x

## 任务文件组织差异

不同的测试任务可能包含不同数量和类型的文件，这反映了任务复杂性和测试方式的差异：

### 简单任务结构
如tasks/silu目录下可能只包含：
- **Makefile** - 编译脚本，执行hipcc silu.hip → applications_silu

### 复杂任务结构
如tasks/assign_score_withk目录可能包含：
- **src/*.hip** - 待优化的HIP kernel源码
- **test_assign_score_withk.py** - 主测试脚本
- **_wrapper.py** - Python层封装，方便调用kernel
- **kernel_loader.py** - 动态加载编译好的kernel
- **.pt文件** - 输入测试数据
- **expected_.pt文件** - 正确性验证的参考答案

> [!tip] 
> 这种文件组织的差异反映了不同任务的测试方式选择：C++自包含测试 vs Python+PyTorch框架测试。

## 配置修改指南

当需要修改任务配置时，AIG-Eval提供了清晰的修改路径：

### 添加新任务
1. 在tasks/目录下创建新的文件夹结构
2. 编写config.yaml和源代码文件
3. 在主config.yaml的tasks列表中添加任务路径

### 修改现有任务
直接编辑对应任务目录下的config.yaml文件，调整相关配置参数即可。

### 选择运行任务
在主config.yaml的tasks列表中配置要运行的任务，支持多任务选择。

通过这种灵活而强大的任务配置管理系统，AIG-Eval能够适应各种GPU kernel优化场景，为AI Agent评测提供标准化的任务接口和执行环境。
