# MCP 集成与工具调用

## MCP 在工作流中的战略地位

在 mini-swe-agent 的设计哲学中，MCP（Model Context Protocol）扮演着不可或缺的角色。值得注意的是，在 MCP 模式下，工作流的第一步被强制要求调用 MCP，这种设计的背后蕴含着深层的战略考量。

### 为什么第一步必须是 MCP？

MCP 调用作为工作流的开端，主要承担以下关键职责：

1. **获取优化方向**：通过分析任务特性，确定最优的执行路径
2. **提供最佳实践**：基于知识库提供经过验证的解决方案模式
3. **识别硬件限制**：评估目标环境的约束条件，避免不切实际的优化方案

> [!warning] MCP 的必要性
> 跳过 MCP 调用可能会导致 Agent 在错误的方向上浪费大量计算资源，或者在不知情的情况下违反目标环境的约束条件。

## @amd 工具生态系统详解

ai-devtool MCP server 提供了一套完整的工具生态系统，通过 `@amd:` 前缀的指令实现不同功能的专业化处理。

### @amd:query - 主题搜索工具

```bash
@amd:query {"topic": "..."}
```

这是系统的知识检索入口，允许 Agent 从庞大的知识库中搜索特定主题的信息。使用场景包括：
- 查找特定编程概念的定义
- 搜索最佳实践指南
- 获取特定问题的解决方案

> [!tip] 有效的查询策略
- 使用精确的关键词而非模糊描述
- 结合上下文信息缩小搜索范围
- 多次迭代查询以获得全面信息

### @amd:example - 示例获取工具

```bash
@amd:example {"category": "...", "use_case": "..."}
```

这个工具专注于提供实际的代码示例和使用案例，参数说明：
- `category`：示例所属的技术类别（如算法、数据结构、设计模式等）
- `use_case`：具体的使用场景描述

通过精确的类别和场景组合，Agent 能够获得高度相关的示例代码，大大提升开发效率。

### @amd:optimize - 优化建议工具

```bash
@amd:optimize {"code_type": "...", "context": "..."}
```

这是一个基于描述的优化建议工具，需要注意的关键限制是：

> [!warning] 代码传递限制
> `@amd:optimize` 工具不支持直接传入代码进行分析，只能接受代码类型的描述和上下文信息。

这种设计虽然看似限制了工具的能力，但实际上促使 Agent 学会更高层次的抽象和描述能力。

## 代码优化的间接实现策略

面对无法直接传递代码的限制，Agent 需要采用更智能的策略来获得代码优化建议。

### 问题描述重构

当需要对具体代码进行优化时，Agent 应该将问题转化为高层次的技术问题描述：

```bash
@amd:troubleshoot {
  "error_message": "使用了 shared memory 进行 tiling，但性能只提升了 10%，预期应该更高"
}
```

这种方法的巧妙之处在于：

1. **抽象化问题**：将具体的代码实现转化为技术挑战描述
2. **聚焦核心问题**：强调性能差距而非实现细节
3. **引导专业建议**：促使 MCP 系统提供针对性的优化策略

### 描述式优化的优势

虽然不能直接分析代码，但这种间接方法实际上具有独特优势：

- **促进思考**：迫使 Agent 深入理解问题的本质
- **通用性强**：优化建议可以应用于多种类似场景
- **避免依赖**：不会因为特定代码的局限性而影响建议质量

## LLM 工具调用的前提条件

让 LLM 成功生成类似 `@amd:query {"topic": "xxx"}` 这样的查询指令，需要满足三个关键条件：

### 1. 工具定义（Tool Definition）

必须明确告诉 LLM 有哪些工具可用，以及每个工具的具体用途。这就像提供了一个完整的工具菜单：
- 工具名称和功能描述
- 参数格式和要求
- 适用场景和限制条件

### 2. 意图识别（Intent Recognition）

LLM 需要学会从用户的模糊需求中识别出最合适的工具调用方式。这要求：
- 理解用户的真实意图
- 匹配最相关的工具
- 确定调用的时机

### 3. 槽位填充（Slot Filling）

从用户的自然语言描述中提取并填充工具所需的参数：
- 识别关键词和实体
- 映射到工具参数
- 验证参数的完整性和有效性

> [!example] 完整的调用链
> 用户需求："我想了解如何优化矩阵运算的性能"
>
> LLM 处理过程：
> 1. 意图识别 → 需要性能优化建议
> 2. 工具选择 → @amd:optimize
> 3. 参数提取 → code_type: "matrix_operations", context: "performance_optimization"

## MCP 集成的架构优势

### 模块化设计

MCP 集成采用了清晰的模块化架构：
- 核心功能与工具调用分离
- 独立的提示词管理系统
- 灵活的工具注册机制

### 扩展性保证

通过标准化的工具接口，MCP 系统能够：
- 轻松添加新的工具类型
- 保持向后兼容性
- 支持第三方工具集成

## 实际应用场景

### 性能优化工作流

1. **分析阶段**：使用 `@amd:query` 了解性能分析的最佳实践
2. **定位瓶颈**：通过 `@amd:example` 获取性能分析代码示例
3. **优化建议**：利用 `@amd:optimize` 获得针对性的优化策略

### 学习新领域

1. **基础概念**：通过 `@amd:query` 建立知识框架
2. **实践案例**：使用 `@amd:example` 学习具体实现
3. **深入应用**：结合 `@amd:optimize` 掌握高级技巧

这种系统化的工具使用方式，使得 Agent 能够在复杂的技术环境中保持高效的学习和解决问题的能力。
