# CLAUDE.md 规范管理

## 概述

CLAUDE.md 是 Claude Code 的核心配置文件，它定义了项目的长期规则和工程约定。每当 Claude Code 启动时，会自动加载项目根目录下的 CLAUDE.md 文件，将其内容注入到会话上下文中。本文将系统介绍如何设计、维护和优化 CLAUDE.md 文件。

## CLAUDE.md 的作用

> [!info] **核心价值**
> - 让 Claude 在任何任务开始前就具备关键项目信息
> - 避免每次在 prompt 里重复复杂信息
> - 减少提示词开销并避免信息冗余
> - 将长期规则固化，确保行为一致性

### 典型使用场景

使用 `/memory` 命令时特别适合更新 CLAUDE.md：

- 让 Claude 记住团队约定
- 把规范流程固定下来（如 [[Git 流程]]、测试规范）
- 让未来会话自动携带项目信息
- 整理散落在对话里的重要内容为长期记忆

## CLAUDE.md 的五大信息层

Anthropic 官方推荐的 CLAUDE.md 结构包含五个层次：

| 信息层 | 作用 | 示例 |
|--------|------|------|
| **层1：项目身份** | 让 Claude 知道这是什么项目 | "这是一个 Obsidian Vault 知识库仓库" |
| **层2：工程价值观** | 让 Claude 知道冲突时优先选择什么 | "优先选择简单方案，避免过度设计" |
| **层3：行为边界** | 规定必须遵守和禁止的事项 | "禁止提交包含密钥的文件" |
| **层4：操作方式** | 规定事情应该怎么做 | "使用 /commit-rebase-push 提交代码" |
| **层5：禁区** | 明确永远不该碰什么 | "不要修改 node_modules/ 目录" |

## 内容精简原则

### 为什么需要精简？

> [!danger] **CLAUDE.md 太长的后果**
> - Claude 可能忽略部分内容
> - 长文件影响注意力分配
> - 降低关键规则的执行优先级

精简的规则更容易被 Claude 持久记住和遵循，把文件精炼成最重要的规则和命令能更稳定地影响 Claude 的行为。

### 精简策略

每条规则应该：
- **不超过一行**
- **可执行**（明确具体操作）
- **无歧义**（没有多种解释方式）

> [!tip] **删除 "有点有用" 的规则**
> - 应该删掉所有 "有点有用" 的规则
> - 只保留**非常重要**的规则
> - 记住：少即是多

### 核心三问

设计 CLAUDE.md 内容时，对每条规则问三个问题：

1. **这条规则是否长期有效/对下个 session 有效？**
2. **这条规则是否经常影响 Claude 的决策？**
3. **这条规则是不是机器容易犯错的地方？**

如果三个答案都是"是"，这条规则应该写入 CLAUDE.md。

## 更新策略与时机

### 不要频繁更新

> [!warning] **常见误区**
> - ❌ 每完成一个模块就更新 CLAUDE.md
> - ❌ 记录项目发生了什么
> - ❌ 记录一次性操作细节

正确做法：每完成一个模块后**评估**是否有值得沉淀为长期规则的内容，有就更新，没有就不更新。

### Continuous Improvement Loop

Anthropic Data Infrastructure 团队分享的持续改进循环：

```
每个任务结束
    ↓
让 Claude 总结是否有新的稳定模式或规则
    ↓
重点是**知识蒸馏**（提炼以后也应该一直这样做的东西）
    ↓
而不是**过程记录**（记录发生了什么）
```

### 更新指令模板

任务结束提交前，可以给 Claude 以下指令：

> [!success] **规则审计指令**
> "请总结本模块中是否出现了新的可长期复用的工程规范、架构约定或工作流程变化。请总结本次任务中新增/变更的工程规范或稳定规律（如果有），并给出对 CLAUDE.md 的最小必要更新建议；仅在确实能复用的规则层面更新，避免记录一次性细节。"

然后用自然语言让 Claude 检查 CLAUDE.md 是否反映了最新的规范。

> [!note] **关键认知**
> - CLAUDE.md **不会自动维护**，需要手动维护
> - CLAUDE.md 不是记录项目发生了什么
> - 而是规定项目应该**永远如何运作**

## 最佳实践

### 复杂上下文处理

如果新的 session 需要大量背景/上下文，最佳实践是：

```bash
# 让 Claude 把已知信息写到 .md 文件里
# 然后让新 session 读取这些文件
```

> [!info] **处理复杂任务需求**
> - 把复杂任务需求写入 md 文件
> - 让 Claude Code 读取该 md 文件作为上下文
> - 避免在 prompt 中堆砌大量背景信息

### 常见问题

**Q: CLAUDE.md 会在什么时候被加载？**
A: 在每个 Claude Code 会话启动时自动加入到上下文中。

**Q: 如何正确理解持续改进循环？**
A: 每个任务结束 → 让 Claude 总结是否出现了新的稳定模式或规则，重点是知识蒸馏，而不是过程记录。

**Q: 对于 Claude 总是出错的行为应该如何解决？**
A: 把这些出错的行为全部写成规则，放入 CLAUDE.md。

## 总结

CLAUDE.md 是项目知识管理的核心：

1. **分层设计**：五大信息层覆盖从身份到禁区的完整维度
2. **精简原则**：每条规则一行、可执行、无歧义
3. **按需更新**：只在发现长期稳定模式时更新
4. **知识蒸馏**：提炼可复用规则，而非记录过程

一个设计良好的 CLAUDE.md 文件，能让 Claude Code 像熟悉项目的老成员一样工作，大幅提升协作效率。
